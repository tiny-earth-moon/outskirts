Find unused code in Swift projects

outskirts builds your project, maps what refers to what, and reports the declarations nothing reaches. Open source under the MIT license, for Xcode projects and Swift packages, on macOS and Linux.

Get started View on GitHub

What it finds

  • Unused declarations: classes, structs, enums, protocols, functions and properties
  • Assign-only properties, written but never read
  • Unused imports
  • Redundant public accessibility
  • Unused function parameters
  • Redundant protocol conformances

A lot of this code is not dead weight to throw away: it is often a feature that was never wired up, a leftover from a refactor, or an API waiting for its first caller. outskirts shows you where it is, and you decide.

Results can be reported as xcode, json, csv, github-actions, codeclimate or sarif, among others.

Install and run a first scan

  1. Install with Homebrew:

    brew install tiny-earth-moon/tap/outskirts

    Mint, a prebuilt archive and a build from source are covered in Install. Requirements: macOS 15 and Xcode 26 for Xcode projects and Swift packages, or Linux with Swift 6.1.2 for Swift packages.

  2. From the root of your project, let the guided setup detect the project type, print the full scan command and run it:

    outskirts scan --setup

  3. Later, scan an Xcode project, or a Swift package:

    outskirts scan --project MyApp.xcodeproj --schemes MyApp
outskirts scan

Keep your options in a .outskirts.yml file at the project root. To keep a declaration on purpose, add a // outskirts:ignore comment above it.

Where it runs

  • GitHub Actions

    The outskirts action installs a release, checks its checksum and build provenance, and shows each result as an annotation on the pull request.

  • Visual Studio Code

    The extension runs the installed outskirts from the editor and lists the results in a side bar and in the Problems panel.

  • AI coding agents

    An agent skill teaches a coding agent to scan, triage the results and remove unused code safely; --format agent prints a compact report for it.

  • Xcode

    A run script in an aggregate target shows the results as warnings in the issue navigator, next to the code they point at.

Coming from Periphery

  • A .periphery.yml is still read; .outskirts.yml takes its place when you are ready.
  • Baseline files keep working.
  • The periphery command keeps working as an alias of outskirts.
  • // periphery:ignore comments are still honoured.
  • Installed from tiny-earth-moon/tap/periphery? brew upgrade moves you to outskirts.

In continuous integration

# record today's results
outskirts scan --write-baseline baseline.json

# only new results fail
outskirts scan --baseline baseline.json --strict

# annotations on pull requests
outskirts scan --format github-actions
